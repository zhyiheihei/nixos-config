# pve-5700u（Proxmox VE，Ryzen 5700U）

虚拟化宿主：iGPU 直通、双桥分段、pveproxy 证书由机群 ACME 管线接管。
`hosts/pve-5700u/*.nix` 不写注释，理由记录在本文件。

## 直通与内核

- iGPU（`1002:164c` Vega 8 + `1002:1637` HDMI 音频）直通给 Win11 VM：开 IOMMU、直通
  模式、vfio 早绑定（在 amdgpu 抢占之前扣住设备）。
- `lantian-cachy` 内核缺 `dm_thin_pool`，而 `local-lvm` 薄池承载全部 VM 磁盘；不加载
  该模块 VM 磁盘 LV 无法激活。
- `nvidia` 580 驱动是最后一个支持 P40 的版本（`hardware-configuration.nix` 里的选择）。
- 核显 VAAPI/OpenGL：给 VM/LXC 共享 `/dev/dri/renderD128` 做硬编解码。

## 网络

- 双 2.5G 口（I226-V）分段独立成桥：`br-lan`（eth0，主机地址 + 部分 VM）与
  `br-lan1`（eth1，重负载 VM 专用段）。目标是多 VM 并行时不互抢带宽：两段各占独立
  2.5G 物理通道，跨段零抢占。单口桥结构上不可能成环，交换机侧零依赖。
- 历史：曾尝试 bond 软聚合，但 active-backup 无提速，TLB/ALB 在桥接宿主上会因源 MAC
  固定导致交换机表漂移，均废弃；eth1 原来是 Router VM 的 WAN 腿，VM 已全部停机。
- `br-lan1` 是纯 L2 段无 IP，需要 `ConfigureWithoutCarrier` 才会被 networkd 拉起。

## pveproxy 证书

- 机群 ACME 管线已在 greencloud 签发 `lets-encrypt-pve-5700u.zhyi.xin`（base +
  wildcard），经 `/nix/sync-servers` 同步下来；装成 `pveproxy-ssl`，让
  `https://pve-5700u.zhyi.xin:8006` 呈现受信证书，而不是陈旧的
  `CN=pve-5700u.zhyi.xin` 自签回退。
- `/etc/pve` 是 pmxcfs（FUSE），不允许 `chmod`，所以通过 PVE CLI 安装证书（它会把
  `pveproxy-ssl` 按正确权限写入）。
- 同步下来的证书变化（ACME 续期）时重新运行安装器。

## 备份

活动的 Btrfs swapfile 阻止对整个 `/nix` 做快照，所以本机只备份专用的 VirtioFS 数据卷。

## 媒体中心

- 只在 Sonarr/Radarr 两个应用视图里保留历史 `bt.localhost` 端点。
- 从恢复出来的状态树做递归属主修正（systemd 的 `StateDirectory` 只 chown 顶层目录），
  通过 tmpfiles 在每次激活时执行。
- `bitmagnet` 停用：缺重新生成的 `tmdb.yaml` secret（模块、三个 systemd 服务与 vhost
  都注释掉）；`flexget` 的 cron 也停用。
