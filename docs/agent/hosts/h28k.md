# h28k（H28K 双口小主机，RK3528）

独立的**站点路由器**（`192.168.30.0/24`），不是 home-lan 的成员；目前还在家里
staging，搬迁后 WAN shaping 等参数需按实际线路复核。`hosts/h28k/*.nix` 不写注释，
理由记录在本文件。

## 网络

- `eth0` 是集成 GMAC（站点 LAN `192.168.30.0/24`），`eth1` 是 PCIe RTL8111H
  （IPv4 DHCP 上行）。仓库级前缀分类把 `eth0`/`eth1` 都当 WAN，本机覆盖：eth0 是可信
  LAN、eth1 是不可信 DHCP 上行。
- LAN 地址池 `.100-.249`，网关与 DNS 都在 `192.168.30.1`，本机不跑 DHCP 客户端。
- **MAC 固定**：RK3528 GMAC 的地址来自板级 DT（跨重启稳定），但 PCIe RTL8111H 没有
  烧录 EEPROM MAC，否则每镜像/每 machine-id 都会变，破坏 DHCP 身份与地址稳定性。
  两个口都钉成本地管理的固定地址，让 DHCP 保留与防火墙规则跨刷机保持有效。
- CAKE 只塑 WAN 上行（作者路由器配方：dual-src-host 流隔离 + NAT + diffserv8）。
  远端站点的真实上行速率未知，搬迁后必须按实际带宽改；当前 1G 对应家里 staging
  交换机的端口速率。
- `eth0` 用 `fq_codel` 替换默认的 `mq/pfifo_fast` 根（R5C 的 A/B 测试显示等速或更优
  吞吐下重传减半，见 `docs/human/research/10-router-rx-queue-4.md`）；`eth1` 由
  `systemd.network` 的 `cakeConfig` 塑形，不在这里动。
- 两个口都是单队列（`dwmac-rockchip` / `r8169`），RPS 流表覆盖 2 个队列（每口一个），
  并把每个口的 IRQ 钉到各自 CPU（eth0 是 MAC IRQ，stmmac 的 "sfty" IRQ 未使用；
  eth1 是 PCIe MSI-X 向量），下面关掉 irqbalance 让绑定生效。
- XPS/RPS 的写入是 best-effort：`r8169` 有些属性出现得晚或直接拒绝写入（eth1 的
  `xps_cpus` 只在接口 re-setup 之后出现）；真正验证有效的核心项是 RPS、`fq_codel`、
  EEE 和 IRQ affinity。
- **EEE**：H28K 两个 PHY 都开着激进的 Tx LPI 定时器（RTL8211F 1 秒），按 R5C 配方
  关掉。
- 驱动 reset 或 link 重新初始化会清掉 qdisc/affinity/RPS，而 systemd 仍报 oneshot
  active，所以 `h28k-rps` 每分钟重新断言。
- MPTCP 的系统级 path manager 关闭：单条 DHCP 上行用不上，还能去掉首版路由器镜像的
  一个非必要故障点。

## 防火墙

- 模型镜像作者的 `lt-home-router`：input/output 默认 accept，只写显式 drop——timestamp
  ICMP、ZeroTier 上的 Avahi mDNS、WAN 上永不暴露的端口（`PUBLIC_INPUT`）、来自公网
  接口的新连接；clamp TCP MSS。曾经用 drop-by-default 的 input 链是偏离上游的做法，
  它悄悄切断了 Colmena 部署路径（zt* 上的 SSH/LTNET）。
- CoreDNS 跑在自己的 client netns 里，本机在网关地址上把 TCP+UDP 53 呈现给 LAN。
- Hairpin NAT：LAN 客户端也经网关地址访问转发的服务；`@RESERVED_IPV4` 让内网目的地
  不被 NAT（作者配方）。
- **masquerade 只针对离开 eth1 的流量**：WAN 地址动态，所以 eth1 出站全 NAT；但
  LTNET 与 `192.168.30.0/24` 之间的流量保留源地址（这是对作者
  `oifname != "eth0*"` 规则的有意偏离——那条会把 ZeroTier/LTNET 出站也 NAT 掉，
  H28K 的方案要保持不过 NAT）。
- 站点服务的端口转发在有实体服务时再加进对应位置。

## DHCP / DDNS

- MAC → IP 保留项放 secrets 仓（同作者 `lt-home-router/dhcp.nix` 的
  `reservations.vlan0/vlan5`）。明确指定用户，不依赖 nixpkgs 模块的 DynamicUser。
- `ddns.nix` 保持 `site.zhyi.xin` 指向动态 DHCP WAN，用与家里 router 的
  `ddns-gcore` 同一个 Gcore token（`lego.yaml` 的 `lego-env`）。板子还在家里 staging
  时记录跟随家庭公网 IP，搬迁后要复核。
